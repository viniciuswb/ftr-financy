# Financy Back-end Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GraphQL API in `backend/` where each user registers, logs in, and manages only their own categories and transactions.

**Architecture:** Express 5 serves Apollo Server at `/graphql`; TypeGraphQL builds the schema from decorated classes; thin resolvers call services that hold all Prisma calls. Auth is one JWT checked by an `isAuth` middleware that loads the user into the context, and `@GQLUser()` injects it. Tests are Vitest integration tests that run real operations against a separate SQLite file via `ApolloServer.executeOperation`, plus Supertest for the HTTP/CORS layer.

**Tech Stack:** Node ≥ 20.19, TypeScript 5.9 (ESM, `NodeNext`), Express 5, Apollo Server 5, TypeGraphQL 2.0.0-rc.3, graphql 16, Prisma 7 + SQLite (better-sqlite3 adapter), bcryptjs, jsonwebtoken, Vitest 4, Supertest.

**Spec:** `docs/superpowers/specs/2026-10-26-backend-design.md`

## Global Constraints

- Mandatory: TypeScript, GraphQL, Prisma, SQLite, CORS enabled.
- `backend/.env.example` contains exactly the keys used: `JWT_SECRET=`, `DATABASE_URL=`, `PORT=`, `CORS_ORIGIN=`. Defaults: `PORT` 4000, `CORS_ORIGIN` `http://localhost:5173`.
- Every `@Field`, `@Arg`, `@Query`, `@Mutation`, `@FieldResolver` declares its type explicitly (`() => String`); `tsx` does not emit decorator metadata.
- Pinned versions (exact): `@apollo/server@5.5.1`, `@as-integrations/express5@1.1.2`, `express@5.3.0`, `cors@2.8.6`, `type-graphql@2.0.0-rc.3`, `graphql@16.14.2`, `graphql-scalars@1.26.0`, `class-validator@0.15.1`, `reflect-metadata@0.2.2`, `prisma@7.10.1`, `@prisma/client@7.10.1`, `@prisma/adapter-better-sqlite3@7.10.1`, `jsonwebtoken@9.0.3`, `bcryptjs@3.0.3`, `dotenv@18.0.9`; dev: `typescript@5.9.3`, `tsx@4.23.15`, `vitest@4.1.12`, `supertest`, `@types/node`, `@types/express@5.0.6`, `@types/cors@2.8.19`, `@types/jsonwebtoken@9.0.10`, `@types/supertest`.
- `npm` is the package manager. The project is ESM (`"type": "module"`); relative imports end in `.js`.
- Money: positive integer cents. Transaction `type`: `EXPENSE` | `INCOME`. Dates: `YYYY-MM-DD` strings in the API, stored at UTC midnight.
- Category `icon` ∈ `briefcase-business, car-front, heart-pulse, piggy-bank, shopping-cart, ticket, tool-case, utensils, paw-print, house, gift, dumbbell, book-open, baggage-claim, mailbox, receipt-text`; `color` ∈ `green, blue, purple, pink, red, orange, yellow`.
- Errors are `GraphQLError` with `extensions.code` one of `UNAUTHENTICATED`, `BAD_USER_INPUT`, `NOT_FOUND`; messages in Portuguese (the UI's language). Another user's id behaves exactly like a missing id (`NOT_FOUND`).
- JWT: payload `{ sub: userId }`, signed with `JWT_SECRET`, `expiresIn: "7d"`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Email with different case or surrounding spaces (`" Conta@Teste.com "`) must register and log in as the same account — trim + lowercase everywhere. Test in Task 1.
2. Amount `0` or negative must be rejected (`BAD_USER_INPUT`); GraphQL's `Int` already rejects decimals. Test in Task 4.
3. A malformed date (`"30/11/25"`, `"2025-13-45"`) must be rejected; a valid `"2025-11-30"` must come back exactly `"2025-11-30"` (no timezone shift). Test in Task 4.
4. Moving a transaction (update) into another user's category must fail with `NOT_FOUND`, not silently succeed. Test in Task 4.
5. Whitespace-only `title`/`description`/`name` counts as empty and is rejected; an empty optional category `description` is stored as `null`. Tests in Tasks 2, 3, 4.

- Produces:
  - `prisma` (`src/lib/prisma.ts`): `PrismaClient` built with `new PrismaBetterSqlite3({ url: env.DATABASE_URL })`, client generated to `src/generated/prisma` (generator `prisma-client`), imported from `../generated/prisma/client.js`.

  - `GraphQLContext` (`src/context.ts`): `{ authorization?: string; user?: User }` (`User` = Prisma type).
  - `src/errors.ts`: `unauthenticated(): GraphQLError` (message `"Não autenticado"`), `badInput(message: string): GraphQLError`, `notFound(message: string): GraphQLError`.
  - `src/utils/hash.ts`: `hashPassword(plain: string): Promise<string>` (bcryptjs, cost 10), `comparePassword(plain: string, hash: string): Promise<boolean>`.
  - `src/utils/jwt.ts`: `signToken(userId: string): string`, `verifyToken(token: string): string | null` (returns `sub`, `null` on any failure incl. expiry).

  - `isAuth: MiddlewareFn<GraphQLContext>`: reads `Bearer <token>` from `context.authorization`, verifies, loads the user; on any failure throws `unauthenticated()`; sets `context.user`.
  - `GQLUser(): ParameterDecorator` via `createParameterDecorator<GraphQLContext>(({ context }) => context.user!)`.
  - `UserModel`: `id: ID`, `name: String`, `email: String`, `createdAt: DateTimeISO`, `updatedAt: DateTimeISO` (no password field).
  - `AuthOutput`: `token: String`, `user: UserModel`.
  - GraphQL: `register(data: RegisterInput!): AuthOutput!`, `login(data: LoginInput!): AuthOutput!`, `me: UserModel!` (guarded by `isAuth`).
  - `buildAppSchema(): Promise<GraphQLSchema>` (`src/schema.ts`), `createApolloServer(): Promise<ApolloServer<GraphQLContext>>` (`src/app.ts`).
  - Test helpers (`tests/helpers.ts`): `resetDb(): Promise<void>` (deletes transactions, categories, users in that order); `exec<T = any>(query: string, variables?: Record<string, unknown>, token?: string): Promise<{ data?: T; errors?: GraphQLFormattedError[] }>` (one shared `createApolloServer()`, `executeOperation` with `contextValue: { authorization: token ? \`Bearer ${token}\` : undefined }`, unwraps `body.singleResult`); `errorCode(res): string | undefined` (first error's `extensions.code`); `signUp(overrides?: Partial<{ name: string; email: string; password: string }>): Promise<{ token: string; userId: string }>` (defaults: `"Conta teste"`, unique `user-<n>@teste.com`, `"12345678"`).
